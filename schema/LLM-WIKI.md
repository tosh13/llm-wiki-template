# LLM Wiki 連携

個人用知識ベース `~/llm-wiki/` を Karpathy パターンで維持管理する。スキーマの正本は `~/llm-wiki/CLAUDE.md`。
**Claude Code は全プロジェクトの作業中、以下を自律的に行う。ユーザーへの確認は不要。**

## 人物情報の取り扱い

人物（**本人を含む**）の固有情報を扱うときは `~/.claude/PERSON-PROTOCOL.md` の R1〜R4 を厳守する（SessionStart で提示される。提示が無ければ読む）。要点は、属性を述べる前に正規ローカル記録（entity ページ `wiki/entities/<slug>.md`、組織メンバーの基礎情報は各プロジェクトの一次データ）を必ず読むこと、人名の漢字・役職を推測しないこと、機微情報も別ストアに分離せず entity に `sensitivity` ラベル付きで集約すること。

## Ingest

蓄積すべき知識を見つけたら、`index.md` で既存ページと更新対象を確認して重複を作らず、原資料を `sources/` に格納（外部ファイルは参照ポインタ）、`wiki/` 配下の該当ページと `index.md`・`log.md` を更新する。完了時に「wikiを更新しました: [[ページ名]]」と一言報告する。

対象：プロジェクト横断で有用な概念・知識・事実／意思決定とその理由／人物に関する情報（関係性・接触記録・評価）／法令・規制・基準／比較分析・調査結果。

対象外：プロジェクト固有の一時的な実装詳細／単純なバグ修正・手順実行の記録／git ログやコミット履歴から復元できる情報。

## Query

蓄積知識で答えられそうな質問には、`index.md`（目次）で関連ページを特定してから該当ページを読んで回答する。関連が無ければ wiki 操作はせず進める（毎回全ページを読まない）。回答が新たな分析・整理を含むなら、それをページとして保存する。

## セッション終了時

そのセッションで得た新事実・接触記録・訂正を関与・言及した各 entity へ漏れなく追記し（人物は R3）、追加・更新・移動を `log.md` の先頭に追記して `index.md` を実体と一致させる。グローバル設定に終了ルーチン（`~/.claude/SESSION-END.md` 等）があれば、その Step として実行する。

## 「会話の記録・保存」との使い分け

プロジェクト固有の設計文書・手順書はそのプロジェクトの `docs/` へ。プロジェクト横断の知識・判断・人物情報は `~/llm-wiki/` へ。
